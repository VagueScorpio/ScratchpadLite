Scratchpad Lite - Third-Party Licenses
=====================================

Every package in the shipped application is recorded here, with its license and
why it is in the build. Allowed licenses are MIT, BSD, Apache 2.0, MS-PL and
SIL OFL. No paid or license-key libraries, ever.

A package is added only when what is built into .NET genuinely will not do, and
the cost it adds to startup time and to the size of the .exe is measured and
recorded when it goes in.


Shipped in the application
--------------------------

  DocumentFormat.OpenXml                              3.5.1
    License  MIT
    Why      Reading and writing .docx (Section 7.2). It is Microsoft's own
             Open XML SDK, actively maintained, and the only complete option.
    Cost     Measured when it went in, as Section 2.1 requires: the .exe grew
             from 142.8 MB to 167.5 MB, so about 25 MB. Warm startup did not
             move (705 ms before, 683 ms after), because FormatRegistry creates
             handlers through Lazy<T> and nothing loads the SDK until a .docx is
             actually opened or saved. A test asserts that building the Open
             dialog filter loads neither SDK assembly.

  Markdig                                             0.42.0
    License  BSD-2-Clause
    Why      Reading Markdown (Section 7.2). The standard .NET Markdown
             parser. Writing Markdown is hand-written, because what makes
             written Markdown good is the choice of what to escape, and that
             is a decision rather than a library.
    Cost     Measured when it went in, as Section 2.1 requires: the .exe grew
             from 167.5 MB to 169.2 MB, so about 1.7 MB. Warm startup did not
             move (683 ms before, 656 ms after - within the run-to-run noise),
             because FormatRegistry creates handlers through Lazy<T> and
             nothing loads Markdig until a .md file is actually opened. The
             test that asserts building a dialog filter loads no format
             assembly names Markdig as well as the Open XML SDK.

  System.IO.Packaging                                 10.0.14
    License  MIT
    Why      Pinned explicitly. The version the Open XML SDK asks for
             transitively has a known high-severity advisory
             (GHSA-f32c-w444-8ppv), and this project builds warnings as errors,
             so the restore refused it rather than letting it through quietly.

  The .NET 10 runtime and WPF are inside the single-file .exe. They are
  Microsoft's, under the MIT license:
  https://github.com/dotnet/runtime/blob/main/LICENSE.TXT
  https://github.com/dotnet/wpf/blob/main/LICENSE.TXT


Code written here from a published reference
--------------------------------------------

  WOFF 2.0 decoding                                   Phase 2, shipped
    Follows   Google's woff2 reference implementation
    License   MIT
    Source    https://github.com/google/woff2

    No code is copied. The format is defined by the W3C, and what is taken
    from the reference implementation is the decoding logic for the parts the
    specification describes in prose rather than in a table: the table
    directory's two variable-length integer encodings, and the triplet
    encoding that the glyph coordinates are packed with. The implementation is
    src/ScratchpadLite.Core/Fonts/Woff2Decoder.cs, and it uses the Brotli and
    zlib support built into .NET for the compression.


Planned, with the phase that adds them
--------------------------------------

  System.Text.Encoding.CodePages                      not needed
    Why      Windows-1252 text files. The blueprint expected a package for
             this, and .NET 10 has it built in: adding the reference was
             refused with NU1510, "this package is automatically available".
             CodePagesEncodingProvider is registered on first use in
             TxtFormat with no package at all.


Deliberately not used
---------------------

  Aspose, Syncfusion, Telerik, DevExpress, Spire and similar: paid or
  license-key libraries, excluded by the project rules.

  Nothing was added in Phase 7. Find and replace is this project's own code
  over WPF's TextPointer API, and spell check is the Windows spell checker that
  WPF already uses - the only new dependency is a thirty-line COM declaration
  of ISpellCheckerFactory, which is part of Windows (spellcheck.dll, Windows 8
  and later) and ships with nothing.

  Nothing was added in Phase 8 either. Crash recovery and AutoSave are this
  project's own code over System.Text.Json and the filesystem. Printing uses
  WPF's PrintDialog and System.Printing, both in the Windows Desktop runtime
  that is already published with the app, and PDF export goes through Microsoft
  Print to PDF, a printer driver that ships with Windows 10 and 11 - nothing is
  installed and nothing is redistributed. Single instance uses Mutex and
  System.IO.Pipes from the base libraries, with the pipe's access control from
  System.IO.Pipes.AccessControl, which is part of the Windows Desktop runtime
  rather than a package. No PDF library was taken, which is the point: every
  free one that writes PDF directly would have added megabytes to the .exe to
  do what a printer Windows already has does for nothing.

  Nothing was added in Phase 9, and nothing will be: this is the release. The
  three features it builds are WPF and nothing else. The Paragraph dialog sets
  properties the editor already had. The character grid asks each font for its
  own character map through GlyphTypeface, which is part of WPF. The formatting
  marks are drawn with DrawingContext onto an element of this project's own,
  because no library can draw them - they depend on where this particular
  editor laid this particular text out.

  WOFF, WOFF2, Type 1, .dfont, .eot and .t42 handling is hand-written, because
  no maintained free .NET library covers them. See the WOFF2 note above for
  what the implementation is based on.

  ODT reading and writing is hand-written on ZipArchive and System.Xml.Linq, for
  the same reason.

  Icons come from the Windows icon fonts (Segoe Fluent Icons on Windows 11,
  Segoe MDL2 Assets on Windows 10). They are already on every Windows PC, so
  there is nothing to ship or license.


Embedded resources
------------------

  Adobe Glyph List (AGL)                              Phase 3, shipped
    License  BSD-3-Clause, which is in the file itself
    Source   https://github.com/adobe-type-tools/agl-aglfn
    Why      Mapping Type 1 glyph names to Unicode, so a converted Type 1 font
             gets a real cmap table. A Type 1 font says a glyph is called
             "eacute" and nowhere says that means U+00E9; this list is the only
             way to know.
    Note     Resources/glyphlist.txt, 4281 names, 78 KB, embedded in
             ScratchpadLite.Core and loaded on first use - so a font folder
             with no Type 1 fonts in it never pays for it.
